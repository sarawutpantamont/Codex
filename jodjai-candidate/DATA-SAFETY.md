# จดจ่าย rev02.3 — ข้อมูลในเครื่องและไฟล์สำรอง

## สิ่งที่ patch นี้ป้องกัน

- ก่อนแก้รายการ งบประมาณ หรือธีม เก็บสำเนาข้อมูลดิบในเครื่อง: สำเนาแรกและ 7 สำเนาล่าสุด หากสำรองหรือบันทึกไม่ได้ให้หยุดการเขียน
- บันทึกผ่าน Web Locks และตรวจค่าเดิมก่อนเขียน ป้องกันแท็บรุ่นใหม่นำข้อมูลเก่าเขียนทับอีกแท็บ ถ้าเบราว์เซอร์ไม่รองรับ Web Locks ให้ส่งออกไฟล์ได้แต่หยุดแก้ข้อมูล
- JSON สำรองรวมรายการ งบ และธีม มี SHA-256 สำหรับตรวจไฟล์เสียหาย ไม่มีรหัส PIN เก่าหรือข้อมูลบัญชี ไม่มีข้อมูลถูกส่งขึ้นคลาวด์
- นำเข้าแบบรวม ไม่แทนที่รายการเดิม เมื่อ ID ชนและเนื้อหาต่างกัน เก็บทั้งสองรายการ ภายใต้ ID ใหม่ที่นำเข้าซ้ำได้โดยไม่เพิ่มซ้ำ ปรับรูปแบบข้อมูลด้วย validator เดิมก่อนบันทึก
- การใช้ปุ่มอัปเดตต้องเลือกไฟล์ JSON ที่เก็บไว้เพื่อตรวจว่าตรงกับข้อมูลปัจจุบันก่อน ไม่อ้างว่าไฟล์ถูกเก็บถาวรเพียงเพราะเริ่มดาวน์โหลดแล้ว
- Service worker รุ่นนี้ใช้หน้าเดิมจากแคชใน origin เดิม และปฏิเสธไฟล์อัปเดตที่ตอบด้วย redirect ป้องกันการเปิดเว็บที่เปลี่ยนลิงก์แล้วดูเหมือนข้อมูลว่าง
- ไม่มีการล้าง localStorage หรือเปลี่ยนรูปแบบข้อมูลที่เวอร์ชันก่อนหน้าอ่านอยู่ Legacy PIN keys ยังคงอยู่

## วิธีใช้

1. ตั้งค่า → สำรอง JSON ครบชุด → เก็บไฟล์ใน Files/Downloads หรืออุปกรณ์อื่น ควรใช้ชื่อใหม่และไม่แทนที่ไฟล์เดิมทันที
2. ย้ายเครื่องหรือเปิดลิงก์ใหม่: ตั้งค่า → รวมข้อมูลจาก JSON ตรวจสรุปก่อนยืนยัน หากมี CSV เดิมให้นำเข้าผ่านปุ่ม CSV ได้
3. หากเผลอลบรายการ: เลือกสำเนาย้อนหลัง → รวมข้อมูลจากสำเนา รายการปัจจุบันยังคงอยู่
4. มีอัปเดต: บันทึกฟอร์มที่ค้าง → ดาวน์โหลด JSON → เลือกไฟล์ตรวจสอบ → เปิดเวอร์ชันใหม่ หากข้อมูลเปลี่ยน ต้องสำรองไฟล์ใหม่

## ข้อจำกัดที่ต้องแจ้งตรงไปตรงมา

สำเนาใน localStorage อยู่ในเบราว์เซอร์เดียวกัน หากถูกล้างหรืออุปกรณ์เสีย สำเนาก็อาจหายไปด้วย ต้องมีไฟล์ที่เก็บแยกไว้จึงกู้ได้ การปิดแท็บทั้งหมดอาจทำให้เบราว์เซอร์ activate service worker เอง; data format และ origin เดิมจึงต้องคงไว้เสมอ ไม่อ้างว่ากลไกปุ่มอัปเดตยับยั้งวงจรของเบราว์เซอร์ทุกกรณีได้

การป้องกัน redirect ใช้ได้เมื่อเครื่องติดตั้งและควบคุมด้วย service worker rev02.3 แล้วเท่านั้น ไม่กู้รายการที่หายก่อนหน้านี้ และไม่ย้ายข้อมูลข้าม origin อัตโนมัติ หน้าเก่าที่ถูกรีไดเรกต์แล้วต้องอาศัยไฟล์สำรองหรือข้อมูลเบราว์เซอร์เดิมที่ยังเข้าถึงได้ ห้ามอ้างว่าเราสามารถอ่านข้อมูลจากโทรศัพท์ของผู้ใช้ได้เอง

การเขียนพร้อมกันกับเวอร์ชันเก่าที่ไม่ใช้ Web Locks อยู่นอก protocol นี้ ก่อนอัปเดตให้ปิดแท็บรุ่นเก่าหลังสำรองไฟล์แล้ว ใช้สำเนาดิบหรือไฟล์สำหรับกู้รายการหากมีการแก้ข้ามรุ่น

## ประตูเผยแพร่

เป้าหมายบันทึกไว้ใน release-target.json ก่อนเผยแพร่ตรวจ Site ID, audience และ origin ให้ตรง และรัน release-guard.mjs หาก target เปลี่ยนหรือมี redirect ต้องหยุดและทบทวนการย้ายข้อมูล/ขออนุมัติใหม่ ห้ามเปลี่ยน expected origin เพื่อทำให้ตรวจผ่าน หลังเผยแพร่ตรวจลิงก์เดิมทันที การตรวจล่วงหน้าไม่สามารถรับประกันการเปลี่ยน routing ที่โฮสต์อาจทำระหว่าง deploy ได้; ไฟล์สำรองอิสระและ worker เดิมเป็นการป้องกันอีกชั้นหนึ่ง

เมื่อผู้ใช้อนุมัติ ให้เผยแพร่ไฟล์ dist ตรงกับ candidate ที่ CI ตรวจ ห้ามเผยแพร่ snapshot คนละรุ่นหรือแก้ข้อมูลผู้ใช้จริงในการทดสอบ
